\section{Technical Insights and Lessons Learned}

\subsection{Architecture Lessons}

\textbf{Lesson 1: Start Monolithic, Plan for Microservices}

The Modular Monolith architecture proved optimal for initial development but highlighted scalability limitations. **Key Insight:** For greenfield projects below 10,000 daily active users, a well-structured monolith outperforms premature microservices decomposition. However, designing module boundaries as if microservices exist (clear interfaces, no shared state) facilitates future migration.

\textbf{Lesson 2: NoSQL Schema Design Requires Discipline}

MongoDB's schema flexibility is a double-edged sword. Without Mongoose schema definitions and validation, the database becomes a "data swamp" of inconsistent documents. **Key Insight:** Treat NoSQL schemas with the same rigor as SQL—define schemas, enforce validation, document relationships.

\subsection{Security Lessons}

\textbf{Lesson 3: Defense-in-Depth is Non-Negotiable}

The OWASP ZAP audit (Chapter 5) revealed that "secure by default" is a myth. Even with bcrypt password hashing and JWT authentication, missing HTTP security headers (X-Frame-Options, CSP) exposed attack surfaces. **Key Insight:** Security is a checklist, not an afterthought. Use tools like OWASP ZAP during development, not just pre-deployment.

\textbf{Lesson 4: Environment Variables Are Critical}

A near-miss occurred when the \texttt{.env} file containing API keys was almost committed to GitHub (caught by \texttt{.gitignore} check). **Key Insight:** Configure \texttt{.gitignore} BEFORE writing sensitive credentials. Use tools like \texttt{git-secrets} to scan for accidental secret commits.

\subsection{Testing Lessons}

\textbf{Lesson 5: Manual Testing Does Not Scale}

Regression testing after feature additions consumed 2-3 hours per sprint. **Key Insight:** Even solo projects benefit from automated testing. Invest 20\% of development time in writing Jest/Mocha tests for critical paths (authentication, checkout) to recoup time savings.

\section{Limitations and Constraints}

\subsection{Technical Limitations}

\begin{enumerate}
    \item \textbf{Single-Threaded Node.js Constraint:} CPU-intensive operations (e.g., bcrypt hashing during high registration traffic) block the event loop, degrading response times for all requests. **Mitigation:** Offload to worker threads or separate hashing service.
    
    \item \textbf{No Database Transactions:} Order placement lacks ACID guarantees. Stock deduction and order creation are separate operations, risking inconsistency. **Mitigation:** Implement MongoDB multi-document transactions (requires MongoDB 4.0+, already available in MongoDB Atlas).
    
    \item \textbf{Limited Search Capabilities:} MongoDB text search lacks features like fuzzy matching (typo tolerance), synonyms, or relevance tuning. Searching "macbock" does not return "MacBook". **Mitigation:** Integrate Elasticsearch or Algolia for advanced search.
\end{enumerate}

\subsection{Resource Constraints}

\begin{enumerate}
    \item \textbf{Budget (\$0):} Free-tier hosting (Render.com, MongoDB Atlas) imposes strict limits:
    \begin{itemize}
        \item 512MB RAM → Limits concurrent connections to ~100
        \item Cold start latency → 30-60s delay after inactivity
        \item No CDN → Static assets served from Node.js process (slow for global users)
    \end{itemize}
    
    \item \textbf{Time (3 months):} Solo development with 300 hours total time investment necessitated scope reductions:
    \begin{itemize}
        \item No automated testing framework
        \item Limited admin features (no bulk product import)
        \item Payment simulation only (no real Stripe integration)
    \end{itemize}
\end{enumerate}

\subsection{Medium-Term Enhancements (6-12 Months)}

\begin{enumerate}
    \item \textbf{Microservices Migration:} Decompose monolith into 4 services:
    \begin{itemize}
        \item **Auth Service:** User authentication, JWT issuance (Node.js)
        \item **Catalog Service:** Product search, filtering (Node.js + Elasticsearch)
        \item **Order Service:** Checkout, payment processing (Node.js + MongoDB transactions)
        \item **Inventory Service:** Stock management with event sourcing (Go for performance)
    \end{itemize}
    \textit{Estimated effort: 200 hours + \$300/month infrastructure}
    
    \item \textbf{Recommendation Engine:} Implement collaborative filtering ("Customers who bought X also bought Y") using TensorFlow.js or Python scikit-learn.
    \textit{Estimated effort: 60 hours}
    
    \item \textbf{Mobile Applications:} Develop iOS and Android apps using React Native, sharing business logic with web frontend.
    \textit{Estimated effort: 150 hours + \$99/year Apple Developer + \$25 Google Play}
\end{enumerate}

\section{Personal Reflection}

This capstone project represents the culmination of four years of undergraduate computer science education. Beyond the technical deliverables, the project fostered:

\begin{itemize}
    \item \textbf{Self-Directed Learning:} Technologies like Three.js, Gemini AI, and MongoDB transactions were not covered in coursework, necessitating independent study through official documentation, Stack Overflow, and technical blogs.
    
    \item \textbf{Resilience and Problem-Solving:} Debugging OAuth callback errors (CORS issues), database connection pool exhaustion, and chatbot API rate limiting required systematic troubleshooting and creative solutions.
    
    \item \textbf{Pride in Craftsmanship:} Achieving a 77.5 SUS usability score and positive user feedback validated the effort invested in UI/UX polish. Unlike throw-away academic assignments, this is a portfolio piece demonstrating production-level quality.
\end{itemize}
